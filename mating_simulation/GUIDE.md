# 繁殖シミュレーション 利用ガイド

毎週木曜 10:00 に、Claude がクラウドでシミュレーションを自動で実行し、結果をチャットで報告します。
内容を確認して「登録して」と返すと、今週金曜の交配が Airtable の Mating に予定として登録されます。
使う人は1人（ルーチンを作った Claude アカウントの持ち主）で、Claude デスクトップアプリから操作します。

- 共有用のガイド（コメント可）: [繁殖シミュレーション 利用ガイド](https://claude.ai/artifact/3SaqZzaFBbs9TDqAaFxyyR)
- 計算の詳しい前提（依頼者向けの仕様書）: [仕様書](https://claude.ai/artifact/25Erd2HEDtPGW7p9dwpa7q)

## 概要

1. 木曜 10:00：ルーチン「繁殖シミュレーション 週次」が動き、Airtable を読んでシミュレーションする（クラウドで約5〜10分）。
2. 終わると、デスクトップアプリのセッション一覧に報告が届く。内容は、見る期間の判定、今週金曜の交配リスト、WT の発注が必要なもの、レポートのリンク。
3. 報告を読み、問題なければそのセッションで「登録して」と返す。
4. Claude が Mating に予定（scheduledDate）として登録し、件数を報告する。
5. 金曜に交配したら、担当者が Airtable で matingDate を入れる（今までどおり）。

Airtable への書き込みは、手順3で承認したときだけ行われます。報告を見て何も返さなければ、何も登録されません。

## 初回の準備

PC に Python などを入れる必要はありません。次の5つを一度だけ行います。画面の表記は、アプリの版によって少し違うことがあります。

| 手順 | やること |
| --- | --- |
| 1. デスクトップアプリ | claude.ai/download から Claude デスクトップアプリを入れ、ログインする。Claude Code が使えるプラン（Pro 以上）が必要 |
| 2. GitHub の接続 | claude.ai/code で GitHub を接続し、リポジトリ ylabjp/airtable_scripts へのアクセスを許可する。組織 ylabjp の管理者の承認が要ることがある |
| 3. クラウド環境 | claude.ai/code の環境設定で環境 `mice-simulation` を作り、環境変数に `AIRTABLE_TOKEN=<読み取り専用トークン>` を入れる。ネットワークアクセスは Custom にし、`api.airtable.com` を追加する（既定の許可リストも残す） |
| 4. Airtable コネクタ | claude.ai の設定 → コネクタで Airtable を接続し、Resource_Mice を許可する。Mating への登録はこのコネクタで行う |
| 5. ルーチン | claude.ai/code/routines で毎週木曜 10:00 のルーチンを作る。設定値は下の表 |

トークンは Airtable の Builder Hub → Personal access tokens で作ります。
スコープは `data.records:read` だけ、対象の base は Resource_Mice だけにします。チャットやファイルには貼らず、手順3の欄に直接入れます。

ルーチンの設定値：

| 項目 | 値 |
| --- | --- |
| 実行日時 | 毎週木曜 10:00（日本時間。cron は UTC で `0 1 * * 4`） |
| リポジトリ | ylabjp/airtable_scripts（ブランチ mating-simulation） |
| 環境 | mice-simulation |
| コネクタ | Airtable |
| モデル | Sonnet |
| 指示文 | 下の「ルーチンの指示文」をそのまま貼る |

デスクトップアプリの通知をオンにしておくと、報告が届いたときに知らせが出ます。

### ルーチンの指示文

```
マウス繁殖シミュレーションの週次実行です。日本語で対応してください。

1. リポジトリ ylabjp/airtable_scripts の mating-simulation ブランチに切り替える（git fetch origin mating-simulation && git checkout mating-simulation）。
2. mating_simulation/ フォルダに移動し、mating_simulation/CLAUDE.md を読む。
3. CLAUDE.md の「1. 週次の実行」と「2. チャットへの報告」を行う。シミュレーション（python mating_simulation.py --auto）は時間がかかるので、バックグラウンドで実行して終わるまで待つ。環境変数 AIRTABLE_TOKEN は設定済み（読み取り専用）。

守ること:
- この実行では Airtable に書き込まない。CLAUDE.md の「3. Airtable への登録」は、このセッションでユーザーが明示的に承認したときだけ行う。
- トークンの値を表示・保存しない。results/ をコミット・push しない。コードを変更・push しない。
- 実行や Airtable の読み込みに失敗したら、エラー内容（トークンの値は伏せる）と考えられる原因（ネットワーク許可に api.airtable.com がない、トークンが未設定など）を報告して終わる。
```

## 毎週の使い方

木曜の午前中に報告を読み、金曜の交配の前日までに「登録して」と返すのが基本です。かかる時間は5分ほどです。

1. デスクトップアプリを開き、Code のセッション一覧で「繁殖シミュレーション 週次」のいちばん新しいセッションを開く。ルーチンのページの実行履歴からも開ける。
2. 報告を確認する。見るところは次の4つ。
    1. 先頭に警告がないか（欠品の上限を満たせない系統があるときに出る）
    2. 今週金曜の交配リスト：オスとメスの組み合わせ。体調不良や引退予定の個体が入っていないか
    3. WT の発注：「期限切れ」「今週中に発注」のもの。発注は人が行う
    4. 「購入予定の個体を使う交配」：登録されないので、在庫のメスで代えるかを人が決める
3. 問題なければ、そのセッションで「登録して」と返す。一部を除くときは「M2181 の交配を除いて登録して」のように書く。
4. Claude が登録した件数と、登録しなかったもの（すでに同じ交配があるもの、購入予定の個体を使うもの）を返すので、Airtable の Mating で確かめる。
5. 金曜に交配したら、担当者が matingDate を入れる。取りやめた交配は、その Mating レコードを削除する（残すとメスの交配回数に数えられる）。

詳しい数字やグラフを見たいときだけ、報告にあるレポートのリンクを開きます。木曜以外に実行したいときは、ルーチンのページで「今すぐ実行」を押します。

## よく使う頼み方の例

報告が届いたセッションで、ふつうの言葉で頼めます。再計算を頼むと、結果が出るまで約5〜10分かかります。

| 頼み方 | Claude がすること |
| --- | --- |
| 登録して | 報告した交配を Mating に予定として登録する |
| M2181 の交配を除いて登録して | 指定した交配だけ除いて登録する |
| 購入予定のメスの代わりに F2530 を使って登録して | 指定した個体でその交配を登録する |
| CUL1 だけ見る期間 4.5ヶ月で再計算して | 系統の見る期間を固定して計算し直し、交配リストを出し直す |
| Airtable を直したので、もう一度計算して | 最新の Airtable を読んで計算し直す |
| なぜこのオスが選ばれた？ | 選び方（休止明け・月齢の高い順など）を説明する |
| 先週登録した交配を確認して | Mating の予定レコードを読んで一覧にする |

登録したレコードの変更や削除も頼めますが、Claude は対象のレコードを確認してから行います。Airtable の画面で直接直してもかまいません。

## 困ったとき

失敗したときは、Claude がそのセッションでエラーの内容と考えられる原因を報告します。その週は何も登録されないので、今までどおり手で交配を決めます。

| 症状 | 原因と対処 |
| --- | --- |
| 木曜に報告が届かない | ルーチンが停止していないか、ルーチンのページで確かめる。開始は数分〜10分ほど遅れることがある |
| Airtable の読み込みで失敗する（401・403） | トークンの期限切れ、削除、スコープ不足。Airtable でトークンを作り直し、環境 mice-simulation の `AIRTABLE_TOKEN` を差し替える |
| Airtable につながらない | 環境のネットワーク許可に `api.airtable.com` があるか確かめる |
| 「登録して」で登録できない | ルーチンに Airtable コネクタが付いているか、コネクタが Resource_Mice を許可しているか確かめる |
| 「交配日が過ぎている」と断られる | 金曜以降に先週の報告へ返した。「もう一度計算して」と頼むか、次の木曜を待つ |
| シミュレーションの途中でエラー（Traceback） | プログラムの不具合か、Airtable のデータが想定外。報告をそのまま保守担当に渡す。ルーチンはコードを直さない設定になっている |
| 「実験計画がないため、今週の交配はありません」と報告が来る | Airtable の Plan4Experiment で、すべての計画の MatingPerWeek が 0 か未入力。実験を止めているならそのままでよい。意図していなければ値を戻し、「もう一度計算して」と頼むか、次の木曜を待つ |

登録を間違えたときは、Airtable の Mating で Note が「シミュレーション提案」のレコードを探して直します。

## 設定の変え方と前提

実行日時はルーチンのページで変えられます。それ以外の設定は `mating_simulation.py` の値なので、保守担当に頼みます。

| 設定 | いまの値 | 変える場所 |
| --- | --- | --- |
| 実行日時 | 毎週木曜 10:00 | ルーチンのページ |
| 欠品の上限（系統ごと・年間） | 0.5 ペア | `MAX_MISSING_PAIRS` |
| 見る期間の候補 | 3〜6ヶ月（0.5刻み） | `AUTO_HORIZONS` |
| WT メスの納期 | 3週（仮置き） | `WT_LEAD_WEEKS` |
| ケージ費 | 1ケージ・1日 60円 | `CAGE_COST_PER_DAY` |
| 実験計画（週あたりのペア数） | Airtable の Plan4Experiment | Airtable（次の実行から反映） |

しくみの前提と注意：

- 見る期間は、欠品が上限以下になる期間のうちケージ費が最も安いものを、系統ごとに毎週自動で選びます。上限ぎりぎりの系統は、週によって期間が変わることがあります。
- 子の数は、Mating 履歴の直近1年分から引いています。維持交配（Het × WT）の子は、半分を Het として数えています。
- WT の購入は、必要な週にすぐ使える前提で計算しています。そのため発注期限が「期限切れ」になることがあります。
- 予定として登録した時点で、メスの交配回数に数えられます。取りやめた交配は必ず削除します。
- Airtable の読み取り専用トークンは、環境 mice-simulation を使える人には見えます。書き込みはコネクタで行うので、書き込み用のトークンはありません。
